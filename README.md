# ImageFlow

> **Note:** This README was generated by an AI from the project headers.

> **Toy project** — built for personal learning, no stability guarantees and no intent for external use. That said, PRs are welcome.

A C image processing library with heterogeneous compute support. Automatically dispatches work to CUDA, HIP, or OpenMP depending on what's available at runtime.

## Features

- GPU-accelerated image processing via CUDA and HIP (AMD ROCm)
- OpenMP CPU fallback when no GPU is available
- Unified API — callers don't need to know what backend runs underneath
- Loaded API for resident GPU memory — process multiple operations without round-tripping through host memory
- C11 core with C++17 support for GPU backends

## Building

### Requirements

- CMake ≥ 3.20
- A C11 compiler
- OpenMP (optional but recommended)
- CUDA toolkit (optional)
- ROCm / HIP (optional)

At least one of CUDA or HIP is needed for GPU acceleration. If neither is found, the build falls back to OpenMP only.

### Steps

```bash
mkdir build && cd build
cmake ..
make -j$(nproc)
```

To force a specific build type:

```bash
cmake -DCMAKE_BUILD_TYPE=Release ..
```

CMake will automatically detect CUDA and HIP and enable them if found. No flags needed.

## API

### Image I/O

```c
#include <ImageFlow/io/image.h>

IF_image_t img;
IF_loadImage(&img, "photo.jpg");

// ... process ...

IF_storeImage(&img, "out.jpg");
IF_freeImage(&img);
```

`IF_image_t` holds pixel data as `float*` with width, height, and channel count.

### Operations

```c
IF_grayScale(&img);
IF_invert(&img);
IF_brightness(&img, 1.5f);
```

Accelerator detection happens automatically on first use — no explicit initialization required. The first call probes for CUDA, then HIP, then falls back to OpenMP.

### Loaded API (GPU resident)

For processing a single image with multiple operations, use the loaded API to keep the image resident on the GPU and avoid repeated host↔device transfers:

```c
IF_image_t *dev_img;

IFACC_load(&img, &dev_img);           // upload once
IFACC_loaded_grayScale(&img, dev_img);
IFACC_loaded_brightness(&img, dev_img, 1.2f);
IFACC_retrieve(&dev_img, &img);       // download once
```

> **Note:** Multi-GPU is not planned. The dispatcher picks one accelerator and sticks with it. Intel GPU support (oneAPI/SYCL) is also not planned.

> A builder-pattern pipeline API is planned that will schedule loaded vs. unloaded operations automatically, including CPU/GPU split scheduling. The direct `IF_operationX()` API may be deprecated once that is complete.

### Error handling

All functions return `IF_error_t`. The `IF_CHECK` macro propagates errors with file and line information:

```c
IF_CHECK(IF_loadImage(&img, "photo.jpg"));
IF_CHECK(IF_grayScale(&img));
```

On error it prints to stderr and returns from the calling function.

```c
const char *msg = IF_strerror(err);
IF_logError(stderr, err);
```

## Project Structure

```
include/ImageFlow/
  error.h          — error codes and IF_CHECK macro
  io/image.h       — IF_image_t and I/O functions
  operations.h     — public high-level API
  accelerated/
    acc_wrapper.h  — backend dispatcher
    cuda/backend.h — CUDA backend
    hip/backend.h  — HIP backend
  omp/backend.h    — OpenMP backend

src/
  error.c
  io/image.c
  operations.c
  accelerated/
    acc_wrapper.c  — runtime dispatch table
    cuda/backend.cu
    hip/backend.cpp
  omp/backend.c
```
